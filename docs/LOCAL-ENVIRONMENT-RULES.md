# 第二层规则：本机环境强制约束

本文件与同目录 `AGENTS.md` 配套，在本机执行相关任务时必须遵守，不是可选建议。本机专属路径不得直接作为其他同事设备的默认配置。

## 外盘构建约束（必须遵守）

- 本机可再生构建输出及临时构建缓存统一使用 `/Volumes/ORICO/kemi-build-cache/`，适用于 KEMI、RustDesk、VibeKits、Flutter、Rust、Android 和 Xcode 等构建任务。
- 开始构建前核实 `/Volumes/ORICO` 确已挂载、可写且有足够空间；不得只凭目录存在判断外盘可用，不得在外盘未挂载时创建同名路径并写入系统盘。
- 每个项目或并行任务必须使用独立子目录，禁止不兼容构建共用同一个 `target`、DerivedData 或临时目录；复用项目既有的独立构建路径，不额外发明目录体系。
- 根据工具和既定流程设置 `TMPDIR`、`CARGO_TARGET_DIR`、`GRADLE_USER_HOME`、Flutter build 目录，以及 Xcode 的 `-derivedDataPath` 和 `-archivePath`。不适用的参数无需强行设置，但可再生输出不得静默落回系统盘。
- 源码、Git 数据、证书、密钥、描述文件、文档和正式发布包继续保存在既定正式位置；外盘约束只针对可再生的中间产物及缓存，不授权搬迁或删除受保护数据。
- 不得中断正在执行的构建、签名、归档或发布来迁移目录；从下一条可安全应用配置的构建命令开始生效。
- 外盘不可用或空间不足时，不得静默回退到系统盘；说明具体阻塞，继续不依赖该外盘的已授权工作。更换构建位置须有明确授权并核验容量。

## 团队复用

- 本文件仅适用于当前配置了 ORICO 的设备。其他同事应按其设备建立自己的第二层规则，不必拥有外盘，也不要复制本机的绝对路径。
- 无外盘设备可在其本机规则中指定容量充足的内部数据盘或构建目录，并规定空间检查及不足时的处理方式；这不改变本机必须使用 ORICO 的约束。
