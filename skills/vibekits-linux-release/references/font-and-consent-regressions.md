# Linux 字体回退与确认入口漏编

适用于“旧版中文正常、新版乱码”或“正常允许后仍consent_pending”。案例证据在项目 `docs/acceptance/LINUX101_FONT_REGRESSION_CLEANUP_20261022.md`；其中恢复构建不等于最终修复通过。

- 字体先比较旧版实际构建源的ThemeData/按钮字体、字体资源哈希、系统CJK映射和桌面locale，不只看最新主线。101案例705已有Linux/PAD随包字体分支，744同步漏掉Linux条件；系统字体和TTF并未丢失。保留机器适配时要显式列入冻结输入，新增可检出旧回退的跨平台测试。
- pending不能一律归为用户没点。核对原生请求/响应类型、平台cfg、受保护endpoint allowlist、分发handler、GUI来源校验和人员确认/持久化链路是否在Linux真正编译；案例中Dart能呈现，但Rust处理仍只编Mac/Windows。
- 跨机归档关闭Mac xattrs；Linux root解包使用`tar --no-same-owner`，不要继承Mac UID。101候选顶层误归UID501使不可变GUI检查正确拒绝；核原路径/归属/模式后只纠正本任务部署元数据，不放宽检查、不递归改变其他项目或运行账户。
- 修复不等于放开权限。保留实际GUI/UID/不可变代码校验、原身份、请求有效期、revision CAS、正常原生确认和取消/超时拒绝；不得加CLI/MCP直接写允许记录、默认允许或伪造人员结果。用户已明确授权的正常UI操作仍走现有工具审查，不能绕过拒绝或密码/身份边界。
- 确需独立已授权管理通道修复仿真入口时，先对账原事务、精确源/二进制和占用；有界构建、完整回退、同ID实调后返回原仿真进行正式构建。旧GUI+恢复helper只是恢复状态，不能当最新整包或授权延续验收通过。
- 编译前/后测真实可用空间。只清已确认闲置生成物，保留源码、原SDK、运行版及必要回退。真实系统确认组件须校来源与最终包依赖，缺件失败关闭，不以取消检查换成功。
- 源契约负控、独立模块测试、最终二进制真实IPC/确认、原ID工具调用和新版本实际中文像素是不同证据，逐项记清；未完成的构建不写成已修复。
